# newtxtt 1.060 — corrective release notes

These notes describe the repairs to Michael Sharpe's newtxtt distribution
version 1.059 (2024-03-12). The investigation began with a report that
TS1 text symbols could cause a missing-font error when the variable-width
typewriter family was selected.

The person preparing this corrective release commissioned the investigation
and reviewed, applied and independently tested the resulting patches. I,
ChatGPT (OpenAI), analysed the font distribution, developed and tested the
technical patches and wrote this document. Neither this work nor the present
release implies a transfer of ongoing maintenance responsibility.

Thhe repository used for this update was
https://github.com/jfbu/newtxtt
which records the patches leading from version 1.059 to version 1.060
(and then to 1.061 and 1.062).

Note that the layout in LaTeX-Package-Repositories is slightly different
with the `tools` directory moved, and also the original 1.059 files are available
via the v1.059 tag rather than a zip archive.

## Repairs

1. **Font selection.** The TS1 font definition files referred to nonexistent
   metrics for all four principal shapes of `newtxttz` and for the two
   slanted shapes of `newtxtt`. The references now select the existing
   companion metrics (`newtcxtt`, `newtcxsl`, `newtcxbtt`, `newtcxbsl`,
   each with the appropriate zero-style suffix). Both families deliberately
   share the TS1 metrics; their distinct T1 metrics are retained.

2. **TS1 coverage.** Sixteen slots for glyphs already present in the Type 1
   fonts were restored in all five TS1 encoding vectors and twenty mapped
   TFM files: slots 0–10 (capital accents), 21–22 (dash variants),
   130 (double acute) and 160–161 (quill brackets). Two further slots,
   23 and 31, were supplied for the capital and ascender compound-word marks.
   These use a newly added empty, zero-advance `cwm` glyph in both TS1
   Type 1 fonts, with appropriate metric heights.

3. **T1 coverage.** The previously encoded but missing compound-word mark
   at slot 23 was supplied in the four T1 Type 1 fonts and all 120 mapped
   T1 metrics. Existing glyph programmes, advances, font dimensions and
   other character metrics were preserved. The font map is unchanged.

4. **PDF text extraction.** The new `newtxtt-ts1-unicode.tex` file registers
   36 explicit pdfTeX glyph-to-Unicode mappings, scoped to the twenty TS1
   metrics. It is loaded automatically by both TS1 font definition files.
   Among the corrected mappings are double acute (U+02DD), quill brackets
   (U+2045/U+2046), copyleft (U+1F12F), and the TS1 blank symbol (U+2422).
   This improves text extraction without changing the appearance of the
   glyphs. The initialization is guarded against repetition and is safe
   in the verbatim and active-punctuation contexts tested.

5. **TS1 subset declarations.** The existing declarations of full TS1
   coverage (subset 0) are now supported by the repaired fonts. Both T1
   font definition files also register this coverage, so that direct NFSS
   font selection without loading `newtxtt.sty` does not unnecessarily
   substitute text companion symbols from another family.

## Verification

The distribution was checked against the unmodified 1.059 archive. All
140 mapped metrics (120 T1 and 20 TS1) agree with their encoding vectors
and Type 1 glyphs, including advance widths. All 145 original TFM files
and six Type 1 fonts were included in the reference comparison. The final
audit reported no discrepancies or other errors.

Automated pdfLaTeX tests verified actual font and character selection,
not merely successful compilation. They cover both families, all five
zero styles, with and without `straightquotes`, the principal font shapes,
TS1 commands and accents, Unicode extraction, compound-word marks,
`itemize` bullets, initial TS1 loading in verbatim contexts, and direct
NFSS selection. The final suite passed 10,322 checks in ChatGPT's TeX Live
2025 environment. The release preparer also tested the patches and the
documentation build under TeX Live 2026.

The accompanying repair work produced reproducible Python scripts for
the metric and outline changes, two static audits and the LaTeX regression
suite. Their dependencies are Python 3, fontTools, pypdf and pdfLaTeX;
the outline repair scripts additionally use `t1disasm` and `t1asm`.

## Notes for a future maintainer

- Five legacy, unmapped TFM files remain: `tcxbttz`, `tcxbttzsl`, `tcxttz`,
  `tcxttzsl` and `txttz`. They were retained to avoid removing historical
  files unnecessarily. None is selected by the repaired FD files or map.
- The Unicode mapping additions are specific to pdfTeX; equivalent
  improvements for other engines or DVI-to-PDF drivers were not attempted.
  The decorative leaf glyph has no explicit new Unicode mapping.
- This release is intentionally limited to corrections and verification.
  It does not redesign the typefaces or undertake a general regeneration
  of the font files.
